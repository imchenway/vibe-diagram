# 数据关系图

适用于业务实体、关键字段、所有权和一对一、一对多等数量关系。

- 概念模型中的独立实体保持独立，关键字段只保留影响业务规则的部分，完整字段表可放详情；明确要求完整表结构时，按下节直接展示全部字段。
- 每条实体关系标明 `data-vd-cardinality`，并在可见关系标签中写出对应数量含义。
- 数量关系、所有权、事务边界必须有证据，不能从表名推断。
- 数据运行时的读取、写入、转换、来源与去向使用架构关系图；两类问题都重要时使用关联视图。

图类标记：`data-model`。收益是实体结构与运行时流转含义清楚；取舍是两者同时重要时可能需要两幅图。

## 数据库表结构布局

用户要求查看完整表结构、字段清单、索引或数据库 UML 样式时，采用以下布局。概念模型继续使用关键字段，不强制展开全表。本节规定视觉语法，不提供固定实体、DOM、坐标或生成器。

### 表头与字段位置

- 表使用白底、细灰色直角边框和浅灰表头，配合现有浅色网格。避免圆角卡片、大阴影、独立标签墙和逐行色块。
- 表头居中，真实表名加粗，中文表注释放在同一行后方，以较浅的 `/* 表注释 */` 显示。完整结构视图保留精确表名，入口摘要解释业务含义。
- 字段行从左到右为：键标记、加粗字段名、同行 `/* 字段注释 */`、独立右对齐的类型。注释不能移到字段名下方，类型不能拼进注释或紧接字段名。
- 同一表的键标记列、字段起点和类型右边界统一。类型列宽按本表最长真实类型预留；注释使用中间剩余空间，并留出至少一个字符的列间距。
- 推荐自然字号：表名 22–24px，字段名和类型 17–18px，注释 15–16px；普通行高 28–34px，水平内边距 10–14px。长注释在中间列续行，保持首行与字段名、类型对齐，并增加该行高度；不得省略、遮挡或侵入类型列。
- 使用系统字体栈，涵盖 macOS 和 Windows 中文字体；字段名加粗，注释和类型使用对比度足够的灰色。不要依赖彩色小图标表达唯一语义，键标记同时提供 `PK`、`FK`、`UK` 等文字或可访问说明。
- 普通字段保持来源顺序；按参考图把参与主键的字段放在底部分隔区，复合主键内保持原始顺序。一个字段只显示一次，同时标出其所有键角色。该顺序仅用于展示，不修改数据库物理列顺序。没有主键信息时，不按 `id` 名称猜测。

### 类型、注释与证据

- 完整展示来源中的字段和注释；可空性、默认值、单位及枚举说明在已知时保留。字段注释不是按名称猜出的翻译。
- 类型保留真实数据库含义、长度和精度。只有等价且明确的缩写才可用于展示，例如 PostgreSQL `character varying(64)` → `varchar(64)`；`timestamp(0) without time zone` 可写为 `timestamp(0) 无时区`，不能混同 `timestamptz`。
- 区分“源库没有注释”和“当前材料未提供注释”。只在已检查目录时报告前者；材料缺项时显示后者，不把分析解释写成数据库正式注释。
- 数据库种类、版本、表注释、字段注释、键和索引优先取自用户材料、已有目录或已授权的只读数据库结果。不能为补齐样式访问未授权数据库。

### 索引与约束

- 每张表的字段区下方单独显示“索引与约束”，默认展开。已知索引不得只藏在详情、悬停或图例中；详情只补充原始 DDL 和出处。
- 索引项显示已知的类别（主键、唯一索引、普通索引）、真实名称和按定义顺序排列的列。来源存在时保留排序方向、方法、唯一性、表达式、部分索引条件和包含列。
- 约束与索引分清：`CHECK`、`FOREIGN KEY` 进入约束区；只有主键或唯一约束定义时，展示该约束及字段，不能杜撰支撑索引名、方法或另一条重复索引。
- 复合索引保持列顺序；外键显示源字段 → 目标表和目标字段，已知时保留删除和更新行为。不能因为列名像关联字段就标成外键。
- 未提供索引目录时明确显示“索引定义未提供”；只有检查目录后才能写“无额外索引”。长索引和检查表达式换行显示，不能截断。

### 关系与阅读

- 上下排列直接相关的表，宽度尽量一致。关系线连接对应表边界，线旁标出源字段 → 目标字段；有可靠来源时才标基数。
- 用清楚的图例区分数据库外键、代码查询依赖和待确认关系。保留真实方向和原有关系，不把依赖箭头改成继承三角或聚合菱形。
- 先按完整内容确定表宽和表高，再放置关系线及标签。不能沿用只容纳少量字段的旧高度，或让线穿过字段和索引区。
- 表过多时按真实业务关系分视图，保留所有表、字段和关系。窄窗口在视图内横向滚动，缩放不低于 75%，页面保持纵向阅读。
- 复用共享缩放、详情、关闭和焦点恢复；不要另建详情系统。完整字段与索引始终可见，展开内容只用于证据。分别检查 macOS 与 Windows 字体回退及浏览器行为；一端结果不能代表另一端。

### 适用边界与取舍

完整表结构比关键字段卡片更高、更宽，但读者可直接核对字段含义、类型和索引，减少反复打开详情。通过分视图、注释换行和局部横向滚动处理体积，不能删字段换取紧凑。

这种数据库浏览器式布局属于物理表结构视图，不自动构成严格 UML 记法。用户材料把它称为 UML 时可以说明其数据库视图用途；若明确要求标准 UML 合规，仍按主契约检查严格标准参考，不能仅靠表头、属性分区或箭头宣称合规。
