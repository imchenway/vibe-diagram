# 流程图

适用于先后步骤、判断、分支、汇合、泳道、异常与补偿。

- 先回答“从什么触发，到什么业务结果；哪些条件改变路径”。按业务动作组织主线，不把函数调用、点击记录或时间日志逐条串成节点。技术细节放到对应节点的详情；影响结果的事实与例外仍须可见。
- 开始和结束使用椭圆或胶囊，活动使用矩形，判断使用菱形。节点写一个短动作或问题，一到两行；说明移到图注或详情。不用大图标、装饰插画或整段说明代替流程符号。
- 默认从左到右展示主流程，分支放在主线侧方，汇合接回后续动作。职责交接需要泳道、或纵向确实更易读时，使用 `data-vd-direction="down"`。方向服务于关系，不把长流水账简单旋转九十度。
- 判断的每条出口显示互斥且清楚的业务条件，不用裸 true/false。判断条件只来自证据；确实没有分支的流程允许是短直线，不为了图形丰富编造判断。
- 分支实际汇合时画出汇合，重试或补偿回路写明条件与限制。
- 需要职责时增加泳道；泳道表示真实角色，跨泳道箭头显示交接，不复制同一角色来方便排版。
- 异常在真实发生点分出，并接到恢复、拒绝或终止结果；不为压缩长度省略失败路径。
- 主线相邻节点中心对齐、优先直连；转折只用于分支、回路或避障。回路走主线外侧，箭头始终落在真实形状边缘。箭头保持小于节点正文高度，不在每条边添加重复“下一步”。
- 长流程按真实阶段或职责组织，阶段视图保留交接和异常出口；禁止为凑成横排而删关系、缩字或强制蛇形折返。

图类标记：`business-flow`。流程与泳道共用按文字测量、中心对齐和避障；嵌套泳道可手工编排。收益是短主线、真实分支和明确结果能一起阅读；取舍是高密度职责图仍需要按业务阶段拆分，并人工检查主线。这里使用通用流程符号，不宣称 UML 或 BPMN 合规。
