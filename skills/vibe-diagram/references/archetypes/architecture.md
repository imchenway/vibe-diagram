# 架构关系图

适用于业务能力、职责、系统组件、依赖、数据流转和因果关系。

- 边界表示真实职责、归属、信任或部署范围，不固定画成三层。
- 用可见关系说明拥有、约束、依赖、调用、读取、写入、发布、消费或转换；不能只列组件。
- 数据流转区分来源、处理、存储与去向。实体数量关系使用数据关系图。
- 因果边必须有证据；未知原因保留假设及验证路径，不能由健康检查推断根因。
- 时间顺序是主要问题时选择流程或时序，不给结构图补假步骤。

图类标记：`architecture`；使用原生 `architecture`，纯数据流可用 `dataflow`。明确 pos/size、边界与真实关系，程序检查和计算走线；复杂形状使用 SVG 接入同一查看器。收益是结构与数据去向共用指导；代价是复杂边界仍需要作者安排空间。
