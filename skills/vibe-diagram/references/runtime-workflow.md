# 运行步骤

## 编写

1. 从当前任务最新文档、证据位置和已有图稿定位本次范围，复用已核对且仍适用的事实与关系，只调查变化部分或未解决问题；来源、结构、范围或外壳契约变化时重新核对。形成私有 Diagram Brief：产品问题、结论、业务影响、规则、关键事实、证据状态和验收含义。
2. 按关系选择五种基础图法中的必要部分，最多读取两种指导；当前上下文已有且未变化的契约、图法和有效标准参考直接复用。Diagram Brief 不是第二套渲染输入。
3. 新图创建独立空白草稿；重画复制仍适用的已交付图为工作副本，保留原文件与稳定编号，仅修改受影响视图。共享行为全部内嵌，最终仍是单文件 HTML。

独立读取合并执行；先定位文件，再按范围读取。完整证据留在本地文件，工具只返回必要片段、问题和来源位置，不反复打印完整 HTML、公共脚本或规范正文。直接编辑图稿并复用已有外壳，不为一次作图另写临时生成器。只在既有结构无法表达本次需求时重构受影响视图。

以下命令仅用于创建新图：

```sh
python3 <skill-root>/scripts/vibe_diagram_scaffold.py --output <draft.html> --title '<图类型｜业务主题>' --lang zh-CN
```

命令拒绝覆盖已有文件，路径冲突时不要重试相同创建命令或覆盖旧图。按 [作者契约](artifact-authoring.md) 替换空内容、清单和占位标记，编写产品可读的主要视图和映射技术证据。常规 SVG 使用共享测量、排版与走线，复杂组合直接编排。不要使用已退役的 --spec、--template、--review-kind、--review-spec 输入，也不重建 DiagramDocumentSpec。

## 检查独立候选

编写时同步维护图形和清单：关键事实及关键问题的目标必须有稳定 id、`data-vd-critical`，并位于加载后可见的主视图；每幅图的可见标题使用 `图类型｜业务主题`。`prepare` 已执行完整静态检查，常规流程直接运行它，不先重复调用相同检查器：

```sh
python3 <skill-root>/scripts/vibe_diagram_artifact.py prepare --input <draft.html> --output <candidate.html>
```

一次收齐错误并集中修正，再重新准备独立候选；只有内容已修改或出现新证据才重跑。单独的 lint 命令仅用于需要专门静态诊断的情况，不在候选已通过时再次重复检查，不新增同义检查器。

修改已有图时加 `--previous <previous.html>`，候选内显示按稳定编号得出的新增、删除、内容变化和手工几何变化。两份图必须有相同 artifactId；不能根据文字相似程度猜身份。自动排版的位置变化不计作内容变化。历史 HTML 只解析，不执行脚本。原生内容若需要元素级对比，可在有稳定编号的元素上标记 `data-vd-compare`。

保存 prepare 返回的完整文件 SHA-256 和字节数；它只证明静态检查和文件一致性。候选修改后必须重新 prepare，不能沿用旧浏览器记录。候选不能覆盖草稿或上一份交付图。

在当前宿主提供的真实浏览器中打开该候选，等待字体与自动排版完成，分别以 1440×900、1280×800、390×844 检查。运行 `VibeDiagramQuality.receipt()`，把三次真实返回值原样保存到一个 JSON 数组文件。每次必须 status=passed、issues=[]，页面上的错误提示可定位具体元素。没有可用浏览器时保留为未验候选，不能模拟记录。

复用已确认可用的宿主入口、标签页和本地服务；能力或连接状态变化时再查找工具，不重复尝试已确认不支持的打开方式。同一页面按顺序切换视口，先核对实际尺寸，再合并该视口的只读布局和状态采集；设置回执不能代替实际尺寸，不能并行修改同一页面的视口。图稿变化后重新检查最终候选，不能复用旧通过记录。

页面就绪、字体等待和只读求值必须有明确期限；宿主支持时，单次默认上限为 10 秒。超时后读取一次实际状态，只有新就绪证据或可修复条件出现时才继续，不持续轮询同一未知结果。工具不支持中止时保留未结束状态，不启动相同调用；无法完成的检查列为未验证，不修改检查器放行宿主异常。

检查缩放、窄屏视图内横滚、节点点击/Enter/空格高亮与 Esc 恢复；存在详情时检查开关和焦点返回；存在对比时检查新增、删除及变化；打印保留完整阅读内容。缩放不能低于 75%，页面只使用页面级纵向滚动。默认不为图片生成、下载或导出增加检查；只有用户明确要求图片时，才检查对应图片产物。

关闭详情完成产品阅读：每个关键问题能否从摘要和主要视图得到答案，业务结论、影响、规则、决策、验收及待确认事项是否清楚，精确证据是否仍可追溯。直接检查渲染后的 HTML 页面及 readingMetrics，核对图例位置、浮层、节点大小、旁支转折、留白和重复长卷；截图仅在排查具体视觉问题时按需使用，不是默认步骤或交付前置条件。记录具体发现及修正后的结果；截图缺失不能当作检查通过。将实际阅读结论写入交付参数，不能用静态或几何通过代替阅读。修复绘图能力时，必须用触发用户反馈的真实需求复验，不能只用简化演示图宣布完成。

失败后只修候选或草稿，保留原交付文件。最多修复三轮仍失败时说明具体问题与未验层，不删关系、藏事实、缩字或放宽检查器来通过。

## 安全交付

```sh
python3 <skill-root>/scripts/vibe_diagram_artifact.py accept --input <candidate.html> --output <final.html> --sha256 <prepare返回的指纹> --report <browser-checks.json> --reading-review '<实际产品阅读结论>'
```

已有 final.html 时必须加 `--previous-sha256 <旧文件完整指纹>`，防止覆盖其他修改。命令检查同一份冻结字节、候选标识、浏览器视口和阅读声明后原子替换；失败不替换最终文件。只返回成功后才提供 final.html 的可点击绝对路径。保留命令返回的最终指纹及字节数，文件一变原凭据即失效。

accept 成功后先给用户可打开的正式 HTML 链接，再完成较长的任务记录和最终说明；保留必需文档，不让整理工作延后首次可用交付。默认不附图片、独立 SVG 文件或图片预览，页面内 SVG 属于 HTML 图稿；只有用户另行明确要求图片时才增加图片产物。

浏览器记录和阅读声明来自实际观察者，交付命令只能检查绑定与记录内容，不能证明观察者做过这些操作。不得伪造 passed。若浏览器暂不可用，只可交付明确标注未验的 candidate，不能声称 accepted。

证据分别表述：artifact-static-valid 是静态结构通过；browser-layout-verified 是指定视口真实检查通过；product-reading-reviewed 是实际产品阅读通过；client-runtime-verified 还需要真实客户端安装、发现、调用、输出、交付、升级与卸载。它们互不替代。
